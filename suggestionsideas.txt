# But I would adjust a few things

There are some places where your current code is doing extra work or where you can deliberately practice better patterns.

## 1. Your `map()` + array + `reduce()` can become one `reduce()`

You currently do:

```js
const prices = [];

todayExpenses.map((entry) => {
  return prices.push(Number(entry.price));
});

const todayTotal = prices.reduce((a, b) => a + b, 0);
```

This works, but `map()` isn't really being used for what it is designed for.

You're essentially saying:

> "Go through the array and build another array, then go through that array again and add everything."

You can practice doing it directly:

```js
const todayTotal = todayExpenses.reduce(
  (total, entry) => total + Number(entry.price),
  0
);
```

Same result, fewer steps.

I'd make the same adjustment to:

```js
const totalExpenditure = [];
Transactions.map(...)
```

and your weekly calculation.

This is a **good exercise for you**, because you're learning to recognize when different array methods are appropriate.

# 2. Your weekly calculation is good practice, but I'd change the boundary

You currently have:

```js
weekEnd.setDate(weekEnd.getDate() + 6);
weekEnd.setHours(23, 59, 59, 999);
```

and:

```js
expenseDate >= weekStart && expenseDate <= weekEnd
```

It's valid.

But I'd practice the pattern you used for your month:

```text
start inclusive
end exclusive
```

For example:

```js
expenseDate >= weekStart && expenseDate < weekEnd
```

where `weekEnd` is **7 days after** `weekStart`.

This is a really useful programming concept because it avoids awkward `23:59:59.999` boundaries.

# 3. Your delete function has an important bug

You currently have:

```js
function deleteTransaction(id) {
  let newExpenses = Transactions.filter((entry) => entry.id !== id);
  setTransactions(newExpenses);
}
```

This changes React's state, but **doesn't update localStorage**.

So:

```text
UI
 ↓
transaction disappears
```

but:

```text
localStorage
 ↓
old transaction still exists
```

Refresh the page and it can come back.

You should practice keeping the two synchronized:

```js
function deleteTransaction(id) {
  const newExpenses = Transactions.filter(
    (entry) => entry.id !== id
  );

  setTransactions(newExpenses);

  localStorage.setItem(
    "Expenses",
    JSON.stringify(newExpenses)
  );
}
```

This is actually a very good lesson in **state vs persistence**.

# 4. Your income has the same state/persistence issue in another way

You calculate:

```js
const incomeList = JSON.parse(localStorage.getItem("Income")) || [];
```

This works because the component rerenders after:

```js
setIncome("");
```

But it's not a particularly clean React pattern.

Later, I'd like you to practice:

```js
const [incomeList, setIncomeList] = useState(...)
```

Then:

```text
incomeList
    ↓
React state
    ↓
UI
```

and localStorage becomes persistence rather than the thing your UI reads directly.

That's a **very important distinction** to understand before you move into backend development.
